Architectural law

The emulator API is the hardware API. Everything targets an abstract gated machine. Whether frames are consumed by the GPU wave emulator or by physical electronics is a backend swap. The product is real software from day one: converter and simulator now, control stack later, no rewrite.

FieldCompilerApp ──┐ fieldc CLI ──┼── FieldUI ── FieldGPU ── FieldCore │ │ │ MachineBackend │ ┌─────────┴─────────┐ │ ▼ ▼ │ EmulatedBackend SerialBackend │ T0 / T1 / T2 RP2350 over USB │ (today) (not built) ▼ RH-1 preset · CAD · papers · receipts

Law L1: no logic above FieldCore. SwiftUI views are pure functions of value structs. Law L2: one core, two front-ends — anything the UI can do, fieldc can do.

Solver tiers

One solver cannot be both true and interactive. Arithmetic forces the split:

TierPhysicsCost classStatus
T0Rayleigh–Sommerfeld / angular-spectrum. Dense linear H: drive → field. Exact adjoint Hᴴ (no autodiff).~msGated (G5)
T0.5Boundary-element scattering off the workpiece~0.1–2 sNot built
T1Staggered-grid acoustic FDTD + sponge. Ring-down for matrix pencil~10–60 s/runGated
T1fConvergent Born Series (optional frequency-domain)~1–4 sNot built
T2Gor'kov radiation potential + drag/gravity; GPU particle push~ms/frameGated (G7)
T3Lumped-capacity thermal; melt / wet / latch; occupancy grid~ms/frameNot built

G5 requires T0’s empty-chamber field to match T1 steady state to <5% relative L2 inside the build volume. When that holds, the interactive viewport is trustworthy.

Inverse solvers (geometry → drive)

  • IBP — iterative back-propagation. Fast, mediocre contrast. Baseline every other method must beat.
  • GS-PAT — Gerchberg–Saxton on the reduced point-to-point matrix. Default multi-trap.
  • Diff-PAT — Adam on analytic ∇L via Hᴴ. Best fidelity for whole-object compile.

Hardware constraints enter as projections inside the loop (amplitude ceiling, phase quantization), not as post-hoc rounding.

Principles wired into code

  • Chord-valued drive — ChordDrive is a set of tones, each with its own per-gate vector. Frequency is address; power is shared across tones, not stacked.
  • Dissolve — .dissolve conjugates every gate amplitude. Tested as energy-flow reversal (net intensity through a box around the workpiece must change sign), not as a label flip.
  • Call-and-response — the chord list is input, target, and stopping test for build. Done when the object rings true.
  • Surface hologram — Z(r) = X₀ + M·Re{Ψ*ref·Ψobj}, machine-agnostic primitive shared with memory/compute plans.

Scan pipeline (M7)

empty-chamber reference │ FDTD pulse-echo (scatterer in chamber) │ differential vs reference │ S[rx][tx] scattering matrix │ matrix pencil → chords (poles + port-vectors) │ .pattern (provenance: measured | inferred) │ Machine View L0 (Kirchhoff–Helmholtz / delay-and-sum) │ gates: G11 round-trip · G15 reciprocity · G14 coverage-aware
  • Gated: .pattern bit-exact round trip (G11); reciprocity on a real S matrix (G15 ~0.001); L1 DORT refuses to image without a measured Green’s function.
  • Chord extraction has recovered a pole at 10.68 kHz against a 10.72 kHz drive — the pencil finds real physics.
  • Still weak: G14 IoU not yet meaningful (reflectivity image ≠ occupancy); drive not SI so force/stiffness claims are blocked.
The Green’s-function trap is the biggest technical risk in imaging: a wrong cavity Green’s function yields a confident, sharp, meaningless picture. Held-out prediction (G18) and phantoms (G19) are the no-moving-parts validation path. Multi-bounce virtual apertures rank first once the cavity is measured.

Formats

ArtifactMeaning
Chord(complex frequency p_k, port-vector r_k). ~100 B. Resolution = chord count. Progressive.
.patternScan output / object hologram. Every chord carries provenance: measured | inferred with no default. Inferred chords are excluded from build acceptance unless explicitly promoted.
.fcodeBuild schedule: frames of per-channel complex drive + verb ADD/REMOVE + RX gates. IO not finished.
STLImport mesh → voxelizer → compile target.
Receipt JSONGate name, metrics, thresholds, device, git SHA, duration. Committed culture: no receipt, no published number.

Scan output = build recipe = acceptance test. One alphabet for all three.

Hardware — RH-1

Free-standing column. Two chambers, three dual-carrier plate assemblies, six optically-addressed holographic panels. Ordinary air. Novelty is arrangement of off-the-shelf parts, not a new material.

SubsystemRole
Build chamberVisible volume above the middle plate. Glass enclosure opens (interlock gates drive to mW listening).
Storage chamberHidden mirror twin below — feedstock sort/stage with the same physics.
Plates ×3Top (faces down), double-faced middle, storage deck (faces up). Sound + EM on each.
Acoustic panels ×624 channels (6 × 4 PMN-PT). Force / muscle.
EM capsMicrowave sensing + axial drive. Twin v1 has no Maxwell solver yet.
Bore / optical stemFeedstock lift + optical sightline. Bore winding inert in v1 software.
BOM classSingle-crystal piezos, FR4-gold PCBs, relaxor drivers, GaN amplifiers, FPGA; later Serial backend to RP2350 over USB.

Carriers: phonons = force. Photons = address and sense. Microwave on the caps is sensing/axial drive, not a fourth marketing “hand.”

Compiler preset build volume: Ø280 × 300 mm. Paper envelope numbers still disagree in places (bore diameter, column section, arcade span). Canonicalize in the RH-1 hardware spec, then update sites.

Gates have already caught real bugs (Gor’kov sign/convention inverting traps; FDTD energy sampling point; element- vs gate-granular propagator OOMs; Diff-PAT mis-scaling; Gram-matrix fake S; unshifted QR emitting f=0 chords). That is the argument for gate-first development.
